# 离线销售版部署与续费

## 用户流程

- 用户从 GitHub 或销售包下载项目，用本地启动器打开。
- 首次打开免费试用 7 天，不需要注册、联网或提供设备 ID。
- 到期后，用户通过订单号、客户名称或其他线下渠道联系授权方。
- 授权方使用私有卖家工具生成新的离线签名授权码。
- 用户在“授权与设置”中粘贴完整授权码，项目在本机验证并显示客户、版本和到期日。

## 卖家工具

`generate-license.mjs` 和 `offline-license-private.pem` 只属于卖家授权工具包，不能提交到公开 Git，也不能放入客户销售包。生成示例：

```bash
node generate-license.mjs --customer "客户名称" --days 365 --edition "专业版"
```

卖家只把输出的 `FWL1....` 授权码发给客户。续费时重新生成一枚新码即可，不需要用户提供设备 ID。

## 本地启动

销售包使用本地启动器绑定 `127.0.0.1`，避免浏览器 `file://` 存储和 WebCrypto 兼容问题。启动器只启动本地页面，不调用外部 API、不上传业务数据。

## 安全边界

- 销售包只包含公钥和验签代码，不包含私钥或授权生成器。
- 纯 HTML/JavaScript 的离线授权属于软门槛；用户可以清除浏览器数据、修改源码或调整系统时间。
- 需要更强保护时，应将项目构建为 Tauri/Electron 应用，把授权校验放进原生层并保存到 appData/系统密钥链。
- 不要把离线网页宣传为不可破解的加密程序；压缩、混淆或加密资源只能提高逆向成本。

## 自测

```bash
node --check app.js
node tests/finance-format-regression.cjs
node --check ../../vendor-license-kit/generate-license.mjs
```

回归脚本覆盖利润表与 Excel 口径、产品成本计算和导入校验、备份校验，以及旧版本迁移后刷新不混入示例成本。

用卖家工具生成测试码，复制到应用的“输入离线授权码”弹窗，验证成功后刷新页面，授权信息仍应保留。
